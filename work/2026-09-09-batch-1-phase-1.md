### Container callable identity closure (2026-09-10)

The audit finding: for a runtime-selected list, dictionary, or set element
whose payload nests a callable, `rebase_callable_rvalue` discarded the
callable's descendant path, so `entry[0](value)` after `callbacks.get(index)`
had no authoritative identity and the forged declared type was trusted. The
existing constant-index regression missed it. The fix and the further gaps
found while closing it:

- `rebase_container_result_callables` preserves every descendant suffix,
  merges the identities of every possible element (equal identities stay
  exact; distinct functions sharing one contract keep the contract without a
  name; differing contracts poison the suffix as `Unknown`), and poisons any
  suffix that some possible element lacks. `keys`/`values`/`items` results
  record element identities under the `__any_element` wildcard; dictionary
  `__index` reads now consult `__map_value_` entries.
- Container mutation (`append`, `insert`, `extend`, `set`, `__set_index`,
  `add`, `setdefault`, `update`, `pop`, `remove`, `sort`, `reverse`, ...)
  collapses exact element identities into merged wildcard identities and
  clears them when an inserted operand carries no identity.
- Returned callables are validated against the declared return contract;
  call results and parameters receive identities derived structurally from
  their declared contracts (tuples, class fields, enum payloads, optionals,
  container elements), so boundary-checked declared contracts are
  authoritative inside a function and forged local metadata for derived
  places is never trusted. Callable contract matching now uses
  `type_pattern_matches` over the destination's type parameters.
- The merge rule also repairs an over-strict rejection: a list holding two
  distinct functions with one contract, selected at runtime, was rejected on
  both backends before this change.

Regressions in the uncommitted type-pattern work, confirmed absent at commit
`3f9f95a` and repaired here: ordinary method-call results inherited their

element), repeatable closures were forbidden from owning any non-Copy capture

### Independent review findings and fail-closed callable identity (2026-09-10)

The commissioned read-only adversarial review (a separate Claude subagent,
because Daybreak Blue was unavailable) reported ten findings against the
container closure. Each is closed with dual-backend regressions in
`batch1_union_pattern_security.rs` under a `Finding N` comment:

1. Aggregate-typed call and return boundaries (tuples, lists, class fields,
   enum and union payloads, optionals) now check every callable position
   structurally against the declared contract, so a callable nested in an
   aggregate cannot cross a boundary under forged local metadata.
2. Closure captures are checked against the closure declaration's parameter
   contracts and identities.
3. A control-flow join poisons disagreeing identities as `Unknown` instead of
   dropping one side; an empty-container marker on one side is neutral.
4. Container mutation with an identity-less operand poisons the receiver.
5. `try` carries the `Ok` payload's identity.
6. `ReadLoan` and multi-destination `WriteLoan` merge identities across every
   possible source or destination.
7. A callee whose declared type is a type parameter (or any other
   non-callable local type) has no contract and is rejected.
8. `validate_canonical_mir_place` rejects the reserved `__any_element` and
   `__task_result` segments in serialized places.
9. `items` results are key/value tuples with independently merged sides;
   `copy` results carry every element identity verbatim.
10. Module constants and task results (`result`, `wait`, `poll`,
    `result_or_none`, `result_or`) carry the declared identities of their
    initializer or started function.

The consumption rule is now fail-closed: an indirect call or task start whose
callee place has no authoritative identity is rejected rather than trusting
`local_types`. Making that rule strict exposed three identity sources the
