# Aura 0.16.0 Preview Release

## Goal

Release Aura 0.16.0 as a technical preview. John asked for it on
2026-11-14.

## Cutoff

The candidate holds everything merged since 0.15.0, up to `ec8541c1`:
freestanding builds (#277), GPU tensors (#279, #281, #284, #285, #291),
Linux on arm64 and native Windows (#276, #282, #283, #286, #287), builds
for other Linux targets and static musl (#289), and the Homebrew, apt and
Chocolatey package files (#288, #290). No other pull request was open, so
no merge hold was needed.

John decided on 2026-11-14 that 0.16.0 skips the packages. The publish
jobs skip themselves while their secrets are missing, the release still
attaches the `.deb` and `.nupkg` files, and no page advertises a package
manager install.

## A Lookup That Grew With The Table

The first instruction count showed `http_api` running 2.7% more
instructions than with 0.15.0 and `http_stream` 1.9% more, the same in
three runs. Every other program was level.

A host function that takes whole values checks its arguments against
`DYNAMIC_HOST_ABI`, and `dynamic_host_abi` finds the function's entry by
comparing names from the top of the table, once for the call and once
for each argument. The tensor work added 45 entries above the `http` ones, so
every `http` call compared 45 more names for each lookup.

A hash map in place of the scan was tried first. It brought `http_api`
and `http_stream` halfway back and cost the programs whose functions sit
near the top of the table more than the scan does: `markdown_render` ran
4.9% more instructions, `docdb` 2.9% more, and `sort_records` 1.1% more.
It was dropped.

The tensor entries are now last in the table, with a comment that says
why and where new modules go. A tensor operation does far more work per
call than the lookup costs. Every older entry is where it was in 0.15.0.
The lookup still costs a scan for each argument; finding the entry once
per call is follow-up work.

## Measurements

On the shared Linux x86-64 container with 4 vCPUs, at the bench size, the
published 0.15.0 archive (run from a worktree of its tag) and a release
build of the candidate were measured in four passes of five runs each,
alternating, and each time is the median of the twenty. The timing
passes ran before the table change above, which moves only the two HTTP
programs, by under 3% of their instructions. Each Aura version also ran
once under callgrind, the candidate after the change. The benchmark
sources are the same in both tags. The table for each program is in
`benchmarks/cross_language/README.md`.

| Measure | Aura 0.15.0 | Aura 0.16.0 |
| --- | ---: | ---: |
| All 34 programs, wall time | 11.9 s | 12.1 s |
| Median Aura / Rust | 2.8x | 2.8x |
| Median Aura / Python 3.13 | 0.35x | 0.36x |
| Programs faster than Python | 31 | 32 |
| Programs above 8x Rust | 0 | 0 |
| Instructions, all 34 programs | 104,729M | 104,721M |

Python takes 45.0 s and Rust 8.7 s in the same passes. These are lower
than the 0.15.0 release's numbers for the same programs (15.6 s, 56.1 s,
10.8 s) because the container was less busy, not because anything got
faster.

Things to know:

- 0.16.0 changes no code that these programs run, and the instruction
  counts say so: no program moves by more than 0.2%.
- The wall time differences are the container's. `file_io` reads 1,059
  ms against 855, and its 0.15.0 medians ran from 679 to 1,147 ms between
  passes. `task_pool` reads 279 ms against 247 with the same instruction
  count. `csv_aggregate` reads 403 ms against 434, which is why 0.15.0
  counts 31 programs faster than Python here and 0.16.0 counts 32.
- `file_io` and `template_render` are still slower than Python.
- Linux hello world built by the candidate is 1,135,576 bytes, against
  1,117,088 for the 0.15.0 archive on the same host. The 18 KB is the
  code that frees a tensor value, which every program links because any
  value can hold one: `tensor_host::release_held`, the drops of
  `TensorNode` and of the CUDA buffer, and the collections they use.

## Work Completed

- Bumped the CLI, compiler, core, runtime, `aura-mem`, root package,
  language server, and VS Code extension to 0.16.0. The semantic
  interface stays 20, and the native cache format stays `v10`.
- Updated `Cargo.lock`, the path crates in `fuzz/Cargo.lock`, and
  `package-lock.json`.
- Pointed the installers, release workflow example, install guides,
  Manual stamp, docs release metadata, CLI README, release process page,
  and book at `v0.16.0-preview`, and reframed the maintained pages as
  Aura 0.16. The seeded randomness promise now covers the 0.16.x series.
  Regenerated `llms.txt` and `llms-full.txt`.
- Reworded the pages that said the Windows archive, the Linux arm64
  archive, and the target packs would come "from the release after
  0.15": the platform table, the install guides, the downloads page, the
  CLI page, and the README.
- Added the CUDA version statement to the tensor manual page: no version
  is enforced, the libraries of CUDA 13, 12, or 11 are opened, CUDA 13.2
  with driver 595.91 on an A40 is what is tested, and 11 and 12 have not
  been run.
- Recorded the results in the cross-language README and the performance
  page.
- Moved the Unreleased entries into the 0.16.0 and extension 0.16.0
  sections.
- Moved the tensor entries of the host function table below the others.

## Release

- PR #292 merged as `91218b26` on 2026-11-15, on a green hosted CI run of
  its final head `8791f2f8`. The annotated `v0.16.0-preview` tag object
  `763aa2b4` points at the merge commit. It is unsigned by choice because
  no repository signing identity is configured. It was pushed on
  2026-11-15 from John's checkout after he approved the tag push.
- Release run `43695720872` passed all thirteen jobs in 32 minutes and
  published at 09:13 UTC. No other CI run was competing for runners. It
  published the Linux x86-64, Linux arm64, macOS arm64, macOS x86-64, and
  Windows x86-64 archives, the four target packs, the docs, the VSIX, and
  `SHA256SUMS`, and published extension 0.16.0 to the Visual Studio
  Marketplace and Open VSX.
- The Homebrew, Chocolatey, and apt publish jobs skipped their push
  steps because their secrets are not set, as John decided. The release
  carries the two `.deb` files and the `.nupkg` as assets, and no page
  advertises them.
- The Linux x86-64 archive matches `SHA256SUMS`, its `aura --version`
  prints `aura 0.16.0-preview (91218b26b464)`, and it builds and runs
  hello world (1,135,576 bytes).
