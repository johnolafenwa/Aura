# 2026-10-16 Batch 5 Step 4: One Entry Point Per Host Builtin

## Goal

Stop programs from linking host builtins they never call, per sections B2
and B3 of the
[Batch 5 design checkpoint](../architecture_docs/19-batch-5-design-checkpoint.md).

## Work Completed

- Every host builtin is its own exported runtime function, such as
  `aura_host_json_parse` or `aura_host_toml_is_valid`. One macro in
  `native_runtime.rs` generates the entries and the `HOST_BUILTIN_SYMBOLS`
  table that maps each qualified name to its symbol.
- The owned-argument builtins live in `crates/aura-runtime/src/host_builtins.rs`,
  one function each. The byte codecs have one function each too.
- Codegen imports a builtin's entry the first time a function calls it and
  passes only the argument buffer and count. It no longer emits the builtin
  name as data, and `aura_direct_host_builtin` is gone.
- The MIR interpreter reaches the same functions through
  `host_builtin_function`, a name-to-function match in `aura-runtime`.
  Native code never references it, so it stays out of user executables.
- B3 needed no new work. Step 2a already replaced the runtime's checker
  registry with the static `DYNAMIC_HOST_ABI` table, and the entries carry
  their builtin name as a constant for diagnostics.
- `random.secure_int` and `random.secure_bytes` keep their scalar runtime
  entries and have no generic entry.
- Cleanup of a resource whose static type is known calls that resource's own
  close entry, such as `aura_direct_close_task_group`. The shared
  `aura_direct_close_value` dispatcher matched every resource kind, so a
  program that closed a task group linked the TLS close path and the rustls
  handshake code under it. Cleanup of a value whose type is not a single
  known resource still uses the shared dispatcher.

## Sizes

Linux x86-64 release executables, before and after this step:

| Program | Before | After |
| --- | --- | --- |
| hello world | 941,224 | 945,320 |
| reference agent | 2,610,712 | 1,687,680 |
| JSON | 1,984,592 | 1,488,200 |
| TLS | 3,532,232 | 3,434,592 |
| WebSocket | 3,727,736 | 3,736,032 |

Per-builtin entries alone took the agent to 2,066,192 bytes. Typed close
entries took it the rest of the way. Hello world and WebSocket moved by less
than one page of text alignment.

The JSON example and the reference agent no longer link `toml`. The agent and
the TLS example no longer link `http` or `httparse`. The contents gate now
requires that, and the Linux baselines for the agent, JSON, and TLS are
lowered to the new sizes. The agent still links about 4 KB of `rustls` drop
glue through the runtime value type, which step 3 would have removed.

## Verification

- `every_host_builtin_has_its_own_native_entry_symbol` failed until the
  runtime exported one entry per registered builtin.
- The dynamic JSON and `str.to_bytes` codegen tests failed until generated
  code called per-builtin entries and stopped carrying builtin names.
- The contents gate failed for `json` and `reference_agent` until `toml`
  left those executables, and for `reference_agent` until `http` left it.
- `direct_cleanup_of_a_known_resource_type_uses_its_own_close_entry` checks
  that task group cleanup calls its typed entry. A runtime test checks each
  typed entry rejects a value of another type.
- The full Rust suite runs one target at a time with `RUST_MIN_STACK` set.
