# Aura 0.8.0 Preview Release

## Goal

Release Aura 0.8.0 as a technical preview after Phase 1 of the plan to
bring Aura to Rust speed on the 30 cross-language programs. John approved
the plan on 2026-10-26, including a preview release after Phase 1.

## Cutoff

The candidate is cut from `main` at `abd8fef`, the merge of PR #154, which
completed Phase 1. It also carries the first two Phase 2 steps, the layout
plan (#149) and specialized generic functions (#158), and the float32
rendering fix (#156).

## Measurements

All on the shared Linux x86-64 container with 4 vCPUs, against the 0.7.1
compiler (`f517376`) on the same machine. The tables for each program are
in `benchmarks/cross_language/README.md` and
`benchmarks/operation_probes/README.md`.

- Wall time at the bench size: all 30 programs 227 s -> 147 s; median
  Aura / Rust 35x -> 16x; median Aura / Python 3.9x -> 2.7x; faster than
  Python on 9 programs, up from 4.
- Instructions at the check size: 14,793M -> 9,323M; median Aura / Rust
  35x -> 14.5x.
- Each operation probe that a Phase 1 step targets now costs at most 14
  times Rust's instructions. `sort_ints` beats Rust at 2,000 elements.
- The raw JSON is in the project files under
  `rust-speed-plan/phase-1-results/`.

`task_pool` is the one regression, 1,508 -> 2,812 ms, while it runs 39%
fewer instructions. The worker-pool phase alone went from about 0.6 s to
1.4 s. Its voluntary context switches went from about 40,000 to 140,000,
and its system time from 0.4 s to 1.4 s. Putting each loop of that phase
back on a held `Range` one at a time showed the cause: only the 16-step
loop in `mix()` restores the old time. Step 1a made each job almost free,
so the four workers drain the job queue and wait on it far more often.
Each wait goes through the central runtime scheduler and parks an OS
thread. Task hand-off belongs to Phase 4 of the plan.
