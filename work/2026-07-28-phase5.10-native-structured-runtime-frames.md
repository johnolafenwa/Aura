# Phase 5.10: native structured runtime frames

- Date: 2026-07-28
- Status: compact-frame correction implemented; final gates in progress

## Goal

Implement provisional ADR-0036 so MIR, direct-native, standalone, CLI JSON,
and editor-tooling surfaces share one typed Aurora call-frame and task-ancestry
model. Remove the deferred three-note parity carve-out without changing
ordinary nonzero program statuses, cleanup precedence, or human diagnostic
spelling.

## Bound contract

- Every structured diagnostic carries `call_frames` and `task_ancestry`
  arrays, including empty arrays for compile-time and pre-user-code failures.
- Call frames are innermost first; task ancestry is youngest first. Every
  frame carries its own defining or spawning source path.
- Runtime frames are captured exactly once before cleanup or task-state reset.
  Human frame prose is synthesized by the renderer and is absent from
  structured `notes`.
- Public diagnostic schema version `1` gains the arrays additively; readers
  ignore unknown members. The compiler-service semantic interface remains
  version `2`.
- JSON-mode direct runs use a private trap-signal pipe plus a separate bounded
  JSON data pipe so a program trap, missing record, and ordinary
  `main() -> int32` nonzero status remain distinct. Native initialization
  hides and marks both descriptors close-on-exec before user code. Human CLI
  and standalone behavior remain direct-rendered.
- Only direct build/launch unavailability may trigger `auto` fallback.
  Post-launch trap, wait, signal, and diagnostic-protocol outcomes are final.
- Both parity normalizers are removed, and every maintained run-fail oracle
  pins the complete human diagnostic.

## Implemented

- Added typed diagnostic call frames and task-ancestry records, additive
  schema-v1 JSON fields, version-2 compiler-analysis records, and exact LSP
  forwarding. Older compatible analysis records default missing arrays to
  empty.
- Added per-module defining and spawning paths, innermost-first call stacks,
  youngest-first task ancestry, and once-only capture before cleanup or task
  state retirement on both execution backends.
- Added native task-local frame storage, depth rejection, reset and key-reuse
  isolation, and exact codegen metadata forwarding through the private runtime
  ABI.
- Replaced the first implementation's eagerly owned native frame vectors and
  strings with validated immutable metadata, inline depth-one call storage,
  persistent shared task ancestry, and trap-time materialization. The scope
  guard no longer retains the full previous task state inline, ancestry
  teardown is iterative, and repeated propagation of an already captured
  diagnostic performs no frame rematerialization.
- Added the two-pipe native JSON protocol: an exact trap-intent marker plus a
  separate bounded EOF-delimited structured record. Native initialization
  takes ownership of both descriptors, marks them close-on-exec, and removes
  both private environment variables before Aurora user code can run.
- Made direct transport validation exact. Ordinary nonzero exits remain
  ordinary statuses; signal termination and missing, malformed, oversized,
  contradictory, or repeated protocol records are hard execution failures.
  Only pre-launch build or launch unavailability may trigger automatic MIR
  fallback.
- Removed both diagnostic-note parity normalizers. All 53 maintained run-fail
  oracles now pin the complete rendered Aurora call chain.
- Updated the maintained manual, tutorials, READMEs, architecture documents,
  changelog, ADR index, and executable reference integrity pins.
