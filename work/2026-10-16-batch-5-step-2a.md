# 2026-10-16 Batch 5 Step 2a: Create aura-runtime

## Goal

Move the native runtime out of `aura-compiler` into a new `aura-runtime`
crate that cannot depend on compiler code, per section A of the
[Batch 5 design checkpoint](../architecture_docs/19-batch-5-design-checkpoint.md).
The shipped archive and every behavior stay the same.

## Work Completed

- New `crates/aura-runtime` with `native_runtime`, `runtime_value`,
  `runtime_reactor`, `union_runtime`, `json_codec`, `bytes_codec`,
  `text_methods`, `randomness`, `runtime_config`, and `ffi`, moved with
  their tests by `git mv`. `aura-compiler` re-exports each module at its old
  path.
- The runtime used to rebuild the checker's builtin registry to validate
  dynamic JSON and byte builtin arguments. `DYNAMIC_HOST_ABI` is a static
  table of those 20 builtins' parameter names and passing modes. A compiler
  test checks it against the builtin signatures.
- `optional_type` and the enum payload place decoder move to `aura-core`.
  The runtime uses `aura_core::integer::integer_type_bounds`. The text method
  opcode lookup moves to `text_methods`.
- Test hooks that `aura-compiler` tests also use, such as allocation budgets
  and the task stack observation recorder, sit behind the runtime's
  `test-support` feature. The array kernel corpus moves to `aura-runtime`
  under the same feature.
- The interpreter's task stack tests and the `aura_native_run` guard test
  move to `aura-compiler`, which owns the MIR runtime.
- `crates/aura-runtime/tests/dependency_boundary.rs` fails if
  `cargo tree -p aura-runtime -e normal` lists `aura-compiler` or any
  `cranelift` crate.
- `aura-compiler` drops the dependencies only the runtime uses.
- Clippy, the hygiene scheduler checks, the TSan scheduler script, the
  compiler coverage script, and release metadata tests cover the new crate.

## Sizes

Programs that call a dynamic JSON or byte builtin no longer link the
checker's builtin registry. Generated wrappers for those builtins did, so
every subject lost it. Linux x86-64 sizes, with the gate now requiring the

## Census For Step 2b

Every example, benchmark input, and `run-pass`, `run-fail`, `check-pass`,
and `check-path-pass` fixture was built with `aura build --backend direct`,
1,050 programs in all. 1,020 build directly. The other 30 build only through
the launcher:

| Count | Cause |
| ---: | --- |
| 27 | The file is a module with no `main` and no top-level script |
| 2 | Direct backend rejects an `int64` literal coerced to `None` or `int32 \| None` |
| 1 | Direct backend MIR validation reports a mutation through a shared loan |

The three direct-backend gaps are in
`check-pass/conditional_expression_contexts.au`,
`check-pass/retained_call_enum_constructor_argument.au`, and
`check-pass/pythonic_convenience_methods.au`.

## Verification

- `cargo test --workspace`: 3,670 passed. Two tests failed in this
  container and pass in hosted CI: `package_io_helpers_cover_local_error_paths`
  needs a non-root user, and
  `loop_backedge_safepoints_prevent_socket_readiness_starvation` is timing
  sensitive under a fully loaded machine.
- One runtime test expected the JSON evaluator's own unknown-name message
  for `json::is_valid`. The static ABI table now rejects that name earlier
  with `unknown dynamic host builtin`, still as `AU4001`.
- `python3 scripts/check-native-binaries.py` passes against a release build.
- `npm run check:clippy`, `cargo fmt --all --check`, and
  `scripts/check-hygiene.sh` pass.
