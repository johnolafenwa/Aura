# Exact integers, decimals and complex arithmetic

The `numbers` module adds arbitrary-size signed integers, exact decimals
and two-component binary64 complex values. ADR 0113 describes their
representation and the scalar conversion rule. The manual, book and
`examples/numbers/exact_numbers.au` show the public API.

## Representation and correctness

Small BigInt values occupy one signed word plus a tag. Small Decimal
values hold a coefficient and exponent. Large values hold an owning
reference to packed unsigned limbs. The scalar representation survives
calls, returns and arithmetic in native code. Standard BigInt addition,
subtraction and multiplication emit checked word operations in the caller.
Overflow takes the arbitrary-precision path. Exact Decimal addition and
multiplication use a compact native kernel with the same fallback.

The initial host suite used a missing list constructor. Correcting those
tests exposed signed zero in fixed-point output. Rounding -0.005 to two
places now prints -0.00. The suite also exercises packed and boxed storage,
carry propagation with unequal limb lengths, word-sized modular powers and
decimal overflow. Native tests cover aliased inputs and the aligned scalar
decimal result slot. Complex division and square root were checked near
the largest finite binary64 value.

An exhaustive union match in BigInt.copy and Decimal.copy exposed a
synthetic native fallthrough. The unmatched MIR edge now ends with an
unreachable terminator. The original branch also contained a speculative
checker change that accepted a scalar-left generic operator and then
selected the wrong type argument. Restoring the existing diagnostic
preserves explicit numeric conversion.

## Verification

The MIR interpreter and a release direct-native compiler matched all 35
output lines in the two fixtures, including promotion, optionals, task
transfer, collection storage, signed overflow and decimal normalization.
The native allocation counters balanced at 222/222 and 98/98. A small
integer sum allocated nine boxes at both 16 and 256 iterations, down from
105 and 1,545 before checked scalar operations moved into the caller.

All 24 numeric kernel tests passed. Native ABI tests checked aliased limbs,
the decimal result slot and the argument counts of every registered host
entry. All 159 language server tests and 1,095 documentation examples
passed.
Z3 verified the runnable example. An independent comparison with Rust
BigInt checked 30,000 word-sized modular powers and 18,000 signed additions
of varying limb lengths, including exact cancellations and carries across
groups. A separate reference calculation checked 60,000 compact decimal
operations.

## Performance

The benchmark runs six matched Aura, Rust and Python programs and checks
every result before reporting medians. The first optimized release passed
the Python target on all six workloads. Fibonacci took 58.017 ms against
Rust's 11.596 ms. Sampling the complete native workload put 62 percent of
its CPU samples in large integer addition. The carry loop now works on
one preallocated buffer in fixed groups of eight limbs. Result lists also
share their unsigned-word type metadata.

The final release passed all six targets in two comparisons on one CPU.
In the initial seven-run check Fibonacci took 34.900 ms, versus 11.668 ms
for Rust and 35.958 ms for Python. Given the small margin, the workloads
were repeated 21 times per language, rotating their order and checking
every result. The longer comparison measured 19.876 ms for Aura,
13.606 ms for Rust and 26.139 ms for Python on Fibonacci. This was the
largest ratio to Rust at 1.46. The VM also ran builds during these tests.

All six median times, the checksums and exact workloads are in
[the benchmark directory](../benchmarks/numbers/README.md).
