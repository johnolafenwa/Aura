# Aura 0.14.0 Preview Release

## Goal

Release Aura 0.14.0 as a technical preview. On 2026-11-10 John asked for
it once the gaps from the 0.13 evaluation and the docdb margin work had
merged, while streaming I/O, trait objects, and FFI v1 continue in their
own threads.

## Cutoff

The candidate is cut from `main` @ `2206fe9`, after the first FFI v1 step
(#259). Since 0.13.0 it holds the rest of the lean-values work (#240 to
#243), compact JSON storage (#245, #248, #251, #254, #255, #257),
associated-type bounds on classes, implementations, enums, and supertraits
(#249, #258), `IntoIterator` for lists (#256), the verification leftovers
and the `float32` soundness fix (#246, #250, #252, #258), and native
library linking with direct foreign calls (#259).

Of the three feature threads still running, only FFI has merged anything:
its first step of five. Struct arguments, callbacks, C strings, and handle
destructors are not in. Nothing of streaming I/O or trait objects is in.

## Measurements

On the shared Linux x86-64 container with 4 vCPUs, at the bench size, the
published 0.13.0 archive (run from a worktree of its tag; the programs'
sources have not changed since) and the candidate were measured in two
passes of five runs each, alternating, and each time is the median of the
ten. Python and Rust medians pool all four runs. Each Aura version also
ran once under callgrind. The table for each program is in
`benchmarks/cross_language/README.md`.

| Measure | Aura 0.13.0 | Aura 0.14.0 |
| --- | ---: | ---: |
| All 30 programs, wall time | 13.1 s | 11.3 s |
| Median Aura / Rust | 3.5x | 3.2x |
| Median Aura / Python 3.13 | 0.38x | 0.37x |
| Programs faster than Python | 25 | 27 |
| Programs above 8x Rust | 0 | 0 |
| Instructions, all 30 programs | 79,853M | 79,670M |

The container was busier than at the 0.13.0 release (Python 38 s instead
of 30 s). `docdb` takes 309 ms instead of 977 (Python 554, Rust 370) and
`json_roundtrip` 287 ms instead of 673 (Python 415), so both now beat
Python. `csv_aggregate` is level with Python (458 ms each), and `file_io`
and `template_render` are still slower. Fifteen programs were faster in
both passes than 0.13.0 was in either.

Two things to know:

- Fifteen programs run 2 to 6% more instructions than with 0.13.0
  (`regex_match` +6.2%, `lzw_compress` +5.9%, `sql_engine` +5.4%), so the
  total is flat although `docdb` runs 46% fewer. One cause is found:
  `aura_direct_vec_empty_tagged` turns the element type into a
  `SharedType` for each new list, about 50 instructions with the name
  comparison (`raytracer`: 250,000 lists, 12M of its 28M extra). The rest
  is not attributed. Times did not follow: `raytracer` read 19% slower in
  the main passes and `regex_match` 7%, but two more alternating passes of
  five runs put them level (89 ms against 88, 541 against 538), with
  `interpreter` 4% and `lzw_compress` 11% faster.
- Linux hello world built by the candidate is 1,162,576 bytes; the
  published 0.13.0 archive builds it at 1,080,264 bytes on the same host
  (text 974,674 to 1,055,334 bytes). The growth was not traced to a change.

## Work Completed

- Bumped the CLI, compiler, core, runtime, root package, language server,
  and VS Code extension to 0.14.0. The semantic interface stays 20, and
  the native cache format stays `v10`.
- Updated `Cargo.lock`, the path crates in `fuzz/Cargo.lock`, and
  `package-lock.json`.
- Pointed the installer, release workflow example, install guides, Manual
  stamp, docs release metadata, CLI README, release process page, and book
  at `v0.14.0-preview`, and reframed the maintained pages as Aura 0.14. The
  seeded randomness promise now covers the 0.14.x series. Regenerated
  `llms.txt` and `llms-full.txt`.
- Fixed Manual text that had gone stale: the generics page listed
  associated types as unavailable, and the limits, concurrency, status,
  and conformance pages said there is no work stealing, though idle
  workers have stolen unstarted tasks since 0.13.0. The book's traits
  chapter now points at associated types instead of denying them.
- Recorded the results in the cross-language README and the performance
  page.
- Added the missing changelog entries (compact JSON, value size, list
  loops over class instances, dictionary entry appends) and moved the
  Unreleased entries into the 0.14.0 and extension 0.14.0 sections.
- `scripts/test_release_metadata.py`, which CI does not run, pinned eight
  uses of the FFI test guard; #259 removed the adapter test, so it now
  pins seven.
