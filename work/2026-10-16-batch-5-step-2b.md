# 2026-10-16 Batch 5 Step 2b: Retire The MIR Launcher

## Goal

Close the direct-backend gaps the step 2a census found, then make
`aura build` emit directly every time, per section B of the
[Batch 5 design checkpoint](../architecture_docs/19-batch-5-design-checkpoint.md).

## Work Completed

- A conditional or match expression with a union expected type looked up a
  union injection at its own span. A conditional starts at its first arm's
  span, so the lookup found that arm's injection and wrapped the whole value
  in it. `3 if false else None` printed as `number 3` under MIR. Lowering now
  leaves the injection to each arm. Fixture:
  `run-pass/conditional_union_arm_injection.au`.
- Builtin collection methods lowered their arguments without the element
  type the checker used, so `list[int32 | None].append(1)` passed a raw
  integer. MIR trapped with `AU4001 union tag test type identity mismatch`
  and direct emission refused the coercion.
  `BuiltinMember::element_typed_argument` names each argument the checker
  types against a receiver type argument: list `append`, `insert`, `set`,
  `remove`, `index`, `count`, `contains`, dict `get` and `remove`, set
  `add`, `remove`, `discard`, Queue `put`, `try_put`, `get_or`, and
  `TaskResult.result_or`. Fixture:
  `run-pass/collection_argument_union_injection.au`.
- `aura build` no longer falls back to a launcher that embeds serialized MIR.
  `--backend auto` and `--backend direct` stay accepted and select the
  direct backend. The CLI drops `build_mir_runtime_binary`, the generated C
  launcher, and its temporary-file helpers. `aura-compiler` drops the
  exported `aura_native_run` entry point and the serialized-MIR entry helpers
  only it used.
- A file with no `main` and no top-level statements fails with `AU2999` and
  writes no output. A launcher build of such a file produced a binary with
  nothing to run.
- The CLI README, the manual's CLI, execution model, conformance, packages,
  and current limits pages, the learn pages, tutorial 01, and the CLI
  architecture doc describe the single build backend.

## Census Result

Of the 30 programs that built only through the launcher:

| Count | Result |
| ---: | --- |
| 27 | No entry point. `aura build` reports `AU2999`. |
| 2 | Fixed above. Both build directly and run. |
| 1 | `check-pass/pythonic_convenience_methods.au`. Not a launcher gap. |

The last program calls `close()` on a pipe bound by a shared
`match child.stdin():`. The checker accepts it, but MIR validation rejects
the mutation through a shared loan. `aura run` fails the same way, so the
launcher binary would also have failed at run time. The checker does not
require a mutable receiver for process, file, or socket resource methods,
although ADR-0061 H1 says the receiver table is enforced at every call
site. The `run-pass` copy of the program uses `match own`. Closing this gap
changes which programs the checker accepts, so it is left for a decision.
