# FFI v1

Date: 2026-11-10

## Goal

Make FFI able to wrap real C libraries such as SQLite, BLAS, or llama.cpp:
library linking, C strings and out-parameters, structs, callbacks, and handle
cleanup. Call overhead within range of Rust and faster than Python's ctypes
and cffi.

## Plan

1. Library linking, direct native calls, and the `symbol` clause.
2. C strings, scalar out-parameters, nullable handle parameters, and
   pointer-only views.
3. `extern "C" class` structs by value and by pointer.
4. Callbacks.
5. Handle destructors, verifier specs for the new forms, a SQLite wrapper
   example, benchmarks against Rust and Python, and the docs.

## Step 1: linking and direct calls

- `[ffi] libraries`, `library_paths`, `frameworks`, and the `[ffi.linux]`
  and `[ffi.macos]` tables. The driver passes them to the linker, and the
  interpreter loads them before the program starts.
- Native code calls the C symbol itself. The per-call adapter
  `aura_direct_ffi_call` and its serialized call description are removed.
- `extern "C" def name(...) -> T symbol "c_name"`.
- A `str` literal argument passes constant bytes.

Measured on the cloud box, release runtime, 20 million calls each:

| Call | Before | After |
| --- | --- | --- |
| `labs(int64)` | 378 ns | 0.65 ns |
| `toupper(int32)` | 370 ns | 1.3 ns |
| `strnlen(str)` | 420 ns | 3.2 ns |
| `atoi(list[uint8])` | 519 ns | 9 ns |

`benchmarks/ffi_calls` runs the same calls from Aura, Rust, and Python
against one C library. Scalar and byte-buffer calls cost what they cost from
Rust, a `str` view about 2 ns more, and Python's ctypes 300 to 770 ns.

## Verification

- `cargo test -p aura --test ffi_acceptance`, which builds a C fixture
