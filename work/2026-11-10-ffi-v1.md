# FFI v1

Date: 2026-11-10

## Goal

Make FFI able to wrap real C libraries such as SQLite, BLAS, or llama.cpp:
library linking, C strings and out-parameters, structs, callbacks, and handle
cleanup. Call overhead within range of Rust and faster than Python's ctypes
and cffi.

## Plan

1. Library linking, direct native calls, and the `symbol` clause.
2. C strings, scalar out-parameters, nullable handle parameters, and
   pointer-only views.
3. `extern "C" class` structs by value and by pointer.
4. Callbacks.
5. Handle destructors, verifier specs for the new forms, a SQLite wrapper
   example, benchmarks against Rust and Python, and the docs.

## Step 1: linking and direct calls

- `[ffi] libraries`, `library_paths`, `frameworks`, and the `[ffi.linux]`
  and `[ffi.macos]` tables. The driver passes them to the linker, and the
  interpreter loads them before the program starts.
- Native code calls the C symbol itself. The per-call adapter
  `aura_direct_ffi_call` and its serialized call description are removed.
- `extern "C" def name(...) -> T symbol "c_name"`.
- A `str` literal argument passes constant bytes.

Measured on the cloud box, release runtime, 20 million calls each:

| Call | Before | After |
| --- | --- | --- |
| `labs(int64)` | 378 ns | 0.65 ns |
| `toupper(int32)` | 370 ns | 1.3 ns |
| `strnlen(str)` | 420 ns | 3.2 ns |
| `atoi(list[uint8])` | 519 ns | 9 ns |

`benchmarks/ffi_calls` runs the same calls from Aura, Rust, and Python
against one C library. Scalar and byte-buffer calls cost what they cost from
Rust, a `str` view about 2 ns more, and Python's ctypes 300 to 770 ns.

## Step 2: C strings, out-parameters, nullable handle parameters

- `cstr` and `cstr | None` as parameter and result types. The parser reads
  `cstr` as `str` and marks the declaration, so the rest of the compiler
  sees a `str`. MIR carries the mark on the extern call.
- `mut` scalar parameters pass the address of a stack word, stored back to
  the argument's place after the call.
- `Handle | None` parameters pass a pointer that may be null, and
  `mut Handle | None` passes a pointer to one.
- The interpreter does the same through libffi, with one heap word for each
  out-parameter.

Measured the same way, nanoseconds per call, Aura then Rust then ctypes then
cffi: `cstr` argument 22, 18, 179, 126. `cstr` result 38, 20, 155, 248.
`mut int64` out-parameter 1.9, 2.0, 359, 158.

## Step 2b: array pointers

- `ptr[T]` and `mut ptr[T]` parameters pass the address of the first
  element of a `list[T]`, for every fixed-width scalar `T`, with no length.
  The parser reads `ptr[T]` as `list[T]` and marks the parameter, as it
  does for `cstr`.
- Built code reads the element address from the list in line when the list
  keeps its elements unboxed, and asks the runtime to move or copy the list
  otherwise. A `mut` pointer also needs storage no other list shares.
- The interpreter packs the elements into a C array for the call and
  unpacks a `mut` one afterward.
- A `mut ptr[bool]` list is checked after the call. A byte other than 0 or 1
  is `AU4001`.

Nanoseconds per call over a list of 8 floats, Aura then Rust then ctypes
then cffi: `ptr[float64]` 2.5, 4.6, 370, 229. `mut ptr[float64]` 2.5, 2.4,
353, 172.

`Array[T]` does not cross as a pointer yet.
