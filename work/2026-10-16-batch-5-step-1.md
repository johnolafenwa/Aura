# 2026-10-16 Batch 5 Step 1: Extract aura-core

## Goal

Land step 1 of the ratified
[Batch 5 design checkpoint](../architecture_docs/19-batch-5-design-checkpoint.md):
a new `aura-core` crate that holds the types both the compiler and the
future runtime crate need, with no behavior change.

## Work Completed

- New `crates/aura-core` with these modules:

  | Module | Contents |
  | --- | --- |
  | `diag` | `Span`, `Diagnostic`, diagnostic codes, runtime source spans and call frames |
  | `integer` | integer kinds, bounds, and parsing helpers |
  | `ops` | `BinaryOp`, `UnaryOp`, `ReceiverKind` |
  | `task` | minimum and maximum task stack bytes |
  | `type_budget` | the type-size budget the checker enforces |
  | `types` | `Type`, `UnionType`, callable and closure contracts, union normalization |

- `diag`, `integer`, and `type_budget` move with their tests by `git mv`.
  The type budget's test-only constructors sit behind the `test-support`
  feature, which `aura-compiler` enables for its own tests.
- `aura-compiler` re-exports every moved item at its old path, so no caller
  changes. Items that were `pub(crate)` are `pub` in `aura-core`.
- `cargo clippy` in `npm run check:clippy` and the compiler coverage
  script cover `aura-core`.
