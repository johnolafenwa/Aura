# Batch 1 phase 2 (H2): Option removal

Started 2026-09-19 on `codex/batch-1-phase-2` from `main` at `b79f9497`.
Design authority: [checkpoint](../architecture_docs/16-batch-1-design-checkpoint.md)
sections D1–D4 and H2 with the ratified overrides Q6 B, Q20 B, Q23 A and the
2026-09-13 closeout rulings; ADR-0052 and ADR-0058 are the reconciled bodies.

## Target

Remove the language builtin `Option[T]`, `Option.Some`/`Option.None`, the
contextual short constructors, and the `T?` suffix across the maintained
surface; `T | None` is the sole optional spelling. Add the compiler-provided
`Lookup[T]` and `Poll[T]` outcome enums (Q23 A) and convert every D3 row. No
compatibility mode, migration diagnostic, alias, or quick fix.

## Compiler and runtime changes

- `Lookup[T]` (`Found`/`Missing`) and `Poll[T]` (`Ready`/`Unavailable`)
  added to every builtin enum table: `builtin_enum_variants`, the name and
  arity tables in the checker, properties (Copy, Transfer, symbolic copy),
  lowering (`is_known_enum_name`, enum layouts, bare-variant inference,
  payload projections `Found_0`/`Ready_0`), analysis (hover, completion,
  variant typing), and the native payload tables. `Lookup` and `Poll` are
  reserved builtin type names like the other builtin generics.
- New type helpers `optional_type(T)` (the normalized `T | None`),
  `lookup_type`, `poll_type`; every former `Option` construction in the
  checker's member results, the MIR result typing table, the native direct
  typing table, the analysis typing table, `call.rs` names/signatures, and
  `builtin_modules.rs` function signatures now uses them per D3.
- Runtime constructors `optional_present/absent/value`, `optional_str_value`,
  `optional_bytes_value`, `lookup_found/missing`, `poll_ready/unavailable`
  replace `option_some/none` in both runtimes and the shared host builtins;
  the `json.dumps` indent and `cwd` argument parsers accept `T | None` union
  values, bare payloads, and `None`. `Queue.poll`/`Task.poll` replace
  `get_or_none`/`result_or_none` in the checker, lowering, both backends, and
  the language server data.
- Removed: the parser's `T?` desugaring and its two lookaheads, the checker's
  contextual `None`→`Option` typing and `Option.Some/None` constructors, the
  lowering's contextual `None` enum variant, the native `Unit`→`Option.None`
  coercion, the Option layout helpers, the analysis Option symbols and the
  stale `Option[` return placeholder (now `| None` → `return None`).
- Defects found by the conversion and fixed in the same change family:
  `next: indirect Node | None` (a member's `indirect` marks the union field,
  as `indirect Node?` did); MIR result typing for the `process.Child` pipe
  members, `wait_or_none`, `process.Pipe.read_*`, and
  `process.Supervisor.wait_or_none` (type-pattern matches on their results
  panicked); the iterative Array-containing clone and drop traverse union
  payloads (4,096-deep optional links copy on a 512 KiB stack); union
  injection marks the inactive members' callable positions known-empty so
  `Tool | None = None` passes the callable-identity boundary; a type arm's
  member takes the scrutinee union's own spelling (a module-qualified
  `process.ExitStatus` member from a parameter type); `list.get` result
  identities project through `Found_0`; the `poll` timeout diagnostics name
  `poll`; the loan-projection type check tolerates a module-qualified
  nominal spelling on one side (a builtin signature's
  `process.SupervisorEvent` versus the enum's own `SupervisorEvent`); a
  union layout plan is keyed by the union's canonical member keys rather
  than its serialized spelling, so a builtin signature's `bool | None` and
  the program's own `bool | None` share one plan instead of colliding as a
  duplicate (every module now carries the optional unions of the builtin
  signatures it embeds); a callable value bound into a union destination
  (`(def(value: int64) -> int64) | None` bindings, list elements, parameters,
  and a generic `own T | None` parameter bound twice) now meets the bare
  destination's complete-contract rule at the checker (`AU2015`, via the
  shared `enforce_callable_destination`), where before only the MIR
  validator refused the program on both backends; reading a bound's method
  as a member of a type-parameter value (`value: int64 = item.size` inside
  `def render[T: Size](item: T)`) is refused by the checker (`AU2005`),
  where before the checker typed the member as the method's result and both
  backends trapped at runtime on a missing field; the shared value renderer
  prints the unit value as `None` (an absent `T | None` value printed empty
  text after the removal, so `print(value)` produced a blank line, lists
  rendered `[, 1]`, and unit payloads rendered `Result.Ok()`; seven run-pass
  sidecars and two unit expectations changed accordingly, with direct parity).
- Coverage companions from the phase's floor check: run-pass

  `trait_view_method_type_param`, `generic_method_type_param_view`,

## Open items

- Shared type-pattern bindings and mutable-receiver builtins: the checker
  accepts `match child.stdin(): case process.Pipe as pipe: pipe.close()` (the
  binding is a shared loan; `close` is not checked against the receiver
  capability the builtin table declares), while the shared MIR validator
  refuses the lowering on both backends ("mutates through shared loan").
  Every builtin resource `close` is `mut self` in the member table but the
  checker enforces receiver capability only at explicit sites. The owned form
  `match own child.stdin(): case process.Pipe as pipe:` is correct and is
  what the manual, tutorials, examples, and fixtures use. Pre-existing
  checker/validator asymmetry made visible by type patterns; the resource
  capability policy (owned-local `close()` without `mut`) must be decided
  before the checker enforces the table generally.
- Deep recursive drop: a 20,000-deep optional link chain (`next: indirect
  Node | None`) or user-enum chain (`Link.Next(node: indirect Node)`) runs
  and prints on the interpreter but the direct binary is terminated by a host
  signal at exit, and the interpreter overflows at 100,000; identical for
  enum links, so pre-existing recursion in native value drop, not a union
  regression. The iterative Array-containing clone now traverses union
  payloads (fixed in this phase; regression test un-ignored).
- Capturing closures at a `(def() -> T) | None` member or a
  `Lookup[def() -> T]` payload: a closure value is refused ("'closure def()
  -> int64' is not a member"); the ratified storage form `Callable[...]`
  packs the closure and `Tool | None` / `Lookup[Tool]` then work on both
  backends (fixed in this phase: union injection now marks the inactive
  members' callable positions known-empty).
- Script-scope narrowing: `found: str | None = "Grace"` followed by
  `if found is not None: print(found.len())` at module scope checks but both
  backends refuse the member call at run time (the narrowing fact is not
  applied to top-level script bindings); the same code inside a function
  works. Pre-existing phase 1 narrowing gap, not Option-specific.
- Diagnostic wording: a qualified builtin constructor without an expected
  type (`b = Lookup.Found(1)`, `Result.Ok(1)`) reports AU2001 "unknown name";
  pre-existing `Result` behaviour, now also for `Lookup`/`Poll`.
- `Lookup` and `Poll` are reserved builtin type names: a user `trait Lookup`
  is refused like the other builtin generics.

- Value-position short-circuit narrowing (`print(x is not None and x)`) is
  refused by the shared MIR validator ("union payload projection has no
  active matching tag proof") on both backends while the statement form
  `if x is not None and x:` works; confirmed identical on the pre-phase
  baseline (`b79f9497`), so it is a pre-existing phase 1 narrowing gap, not
  an Option-removal regression. Recorded for the flow/narrowing follow-up.
- A function type's `|` binds looser than `->`: `def() -> int32 | None` is
  `(def() -> int32) | None`; an optional-returning function value is written
  `def() -> (int32 | None)`. Pre-existing grammar, now documented.
