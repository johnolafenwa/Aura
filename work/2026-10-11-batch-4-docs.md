# Batch 4: Docstrings And Generated API Docs

## Goal

Implement section D of the
[Batch 4 design checkpoint](../architecture_docs/18-batch-4-design-checkpoint.md#d-docstrings-and-generated-api-docs)
and ADR-0056: first-slot and field docstrings, `Args:` parameter sections,
the `AU2042` limits, the shared normalization, removal from executable
lowering, editor presentation, the `aura doc` command, and a docstring
TextMate scope.

## Work Completed

- **Lexer and parser.** Plain triple-quoted strings lex as
  `TripleStringLiteral`. The parser records a complete first-slot triple
  string as `DocString` on the module, class, enum, trait, function, or
  method, and drops the statement. A string on the line directly after a
  field documents the field. A docstring-only trait method stays
  signature-only. A docstring-only function body becomes `pass`.
- **Diagnostics.** `AU2042` is registered. It reports misplaced triple
  strings in class, enum, trait, and `impl` bodies, a docstring over 65,536
  bytes, and public module documentation over 4,194,304 bytes, with measured
  and permitted counts.
- **Presentation.** `normalize_docstring`, `docstring_summary`,
  `docstring_args`, and `docstring_without_args` in `ast.rs` are shared by
  analysis and `aura doc`. Hover appends the sanitized docstring after the
  signature for functions, methods, classes, fields, enums, traits, and
  modules. Implementation methods fall back to the trait method docstring.
  Completion items carry a summary `documentation` field. Signature help
  carries `documentation` and `parameter_documentation`.
- **Language server and extension.** Completion and signature help map the
  new fields to Markdown documentation. The grammar scopes
  statement-position triple strings as `string.quoted.docstring.triple.*`.
- **`aura doc`.** `crates/aura-compiler/src/analysis/api_docs.rs` builds a
  per-module API record and Markdown page. The CLI command checks each
  source and writes pages to standard output or `--out DIR`, as Markdown or
  `--json`.
- **Docs.** New manual page `docs/manual/docstrings.md`, links from the
  lexical, class, function, trait, CLI, diagnostics, and limits pages, a Learn
  section, a tutorial section in `08-tooling.md`, the surface recap, a new
  example `examples/modules/documented_api.au` with
  `examples/modules/pkg/inventory.au`, and ADR-0056 status.

## Verification

- Compiler unit tests for parsing, exclusions, misplaced strings, both
  limits with exact and overflow sizes, normalization, `Args:` parsing,
  presentation escaping, analysis hover, completion and signature help, API
  docs, and a MIR-equality test that proves a docstring edit leaves MIR
  byte-identical.
- Fixtures: `run-pass/docstrings_declarations`, four `parse-fail`
  misplaced-docstring cases, and `check-fail` for a docstring-only trait
  method that stays required. The run-pass fixture and the new example print
  the same output on the MIR and direct backends.
- CLI tests in `crates/aura/tests/doc_command.rs`.
- LSP tests at 100% coverage, extension tests, and documentation examples.

## Follow-Up

- Decorator retention and property documentation land with decorators and
  properties.
- Class constructor calls have no signature help, so constructor
  documentation shows on hover only.
- `aura doc` writes Markdown and JSON. HTML output and cross-page links are
  not implemented.
