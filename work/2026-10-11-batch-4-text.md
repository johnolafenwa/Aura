# Batch 4 Text And Byte Conveniences

## Goal

Implement section C of the Batch 4 design checkpoint
(`architecture_docs/18-batch-4-design-checkpoint.md`): nine `str` methods and
three `bytes` module functions, with their exact traps, on the MIR and direct
backends, plus language-server completion and hover, manual pages, tutorials,
and a maintained example.

## Work Completed

- `str.trim_start`, `trim_end`, `split_once`, `rsplit_once`, `lines`,
  `split_whitespace`, `find`, `count`, and `repeat` are builtin members in
  `call.rs` with signatures and hover documentation. The checker types them in
  `sema.rs`; a wrong argument type is `AU2002` and a missing one is `AU2004`.
- `bytes.starts_with`, `bytes.ends_with`, and `bytes.find` are registered in
  the `bytes` module namespace, so the checker, analysis, and host-builtin
  metadata share one signature.
- `crates/aura-compiler/src/text_methods.rs` holds the shared runtime
  semantics. The MIR interpreter calls it directly. The direct backend lowers
  the nine methods to one dispatcher, `aura_direct_string_text_method`, and
  routes the byte functions through the dynamic byte host-builtin adapter with
  shared borrows. Byte search uses `memchr::memmem` and is linear time.
- Traps: an empty `split_once`/`rsplit_once` separator, an empty `count`
  text, and a negative `repeat` count are `AU4003`. A `repeat` result above
  the 64 MiB string limit, including a size overflow, is `AU4005` before any
  allocation.
- Fixtures: `run-pass/text_conveniences`, `run-pass/text_conveniences_parsing`,
  six `run-fail/text_*` trap fixtures, and four `check-fail` argument fixtures.
- Example `examples/strings/text_parsing.au` with a CLI test that runs it on
  both backends.
- Docs: `docs/manual/api-index.md`, `docs/manual/bytes.md` (new Byte Search
  section), `docs/manual/diagnostics.md`, `docs/manual/current-limits.md`,
  `docs/learn/from-python.md`, `tutorials/07-strings-and-numbers.md`,
  `tutorials/22-bytes.md`, `examples/README.md`, and the ADR-0063
  implementation line.

## Deviation From The Design

The checkpoint said the empty-separator trap matches `split("")`. The
existing `split("")` does not trap, so `split` is unchanged and the new traps
stand on their own. Section C of the design checkpoint records this.
