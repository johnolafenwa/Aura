# Documentation Audit Against 0.16

## Goal

John read "Aura does not run natively on Windows" in the book on
2026-11-15 and asked for every user-facing text to be brought up to date:
the docs, the README files, `llms.txt`, and anything else stale.

## Method

- Searched every Markdown page for claims that a feature is unavailable,
  planned, or tied to an older release, and tested each doubtful claim with
  the released `aura 0.16.0-preview (91218b26b464)` Linux archive.
- Ran a script over the book, the Manual, and the README files that runs
  each Aura block shown with printed output and compares the first error
  line, or the whole standard output, with the page. It compared 204 errors
  and 146 outputs. The real differences were the `for` loop message in two
  book chapters and one Array example that no longer fails.
- Read the Windows code paths in `crates/aura/src/main.rs` and
  `crates/aura-runtime` for the linker, strip, Unix socket, and library
  loading claims.

## Work Completed

Platforms, in pull request #294: the book's installation chapter and five
other book pages, the home page Windows link, the WSL, VS Code, Linux and
downloads pages, and the CI descriptions in four contributor pages.

The Manual:

- `cli-and-tooling.md` said Aura has no Windows support, and described
  linking and stripping for macOS and Linux only.
- `network.md` and `current-limits.md` said Unix domain sockets need a Unix
  host. They work on Windows.
- `ffi.md` and `current-limits.md` said the interpreter loads libraries on
  Unix-family hosts only. It loads them on Windows too.
- `statements.md` listed `yield` as unavailable, `classes.md` listed
  properties, and `bytes.md` and `current-limits.md` listed HMAC and
  constant-time comparison. All four exist.
- `control-plane.md` listed derived codecs as unavailable. JSON derives them.
- Sixteen sentences still said "Aura 0.3", "Aura 0.9", or "Aura 0.12".
- `lexical-structure.md` lacked the contextual words `view`, `type`, `is`,
  `dyn`, `yield`, `export`, `spec`, and the contract clause words.
- `status-and-compatibility.md` named three release archives and had no
  entry for iterators, generators, trait objects, contracts, verification,
  tensors, SIMD, or freestanding builds.
- `index.md` called the book a future plan, called the FFI "v0", left CUDA
  out of the tensor entry, and did not list two pages.
- The Tensor Module page was missing from the site sidebar.

The book: the `for` loop error message in chapters 8.2 and 8.3, "Aura has
no generators" in 8.4, a paragraph in 8.5 about a compiler bug that is
fixed, `yield` in the keyword appendix, and "Aura 0.12" in 10.3.

Other text: the README install section, direction paragraph, link list and
layout table; the home page and positioning page, which listed freestanding
builds, memory access, cross-compilation, and GPU programming as future
work; the architecture guide index and crate list; the status of two design
checkpoints; the examples index; the extension's snippet descriptions; the
contributor guide's LLVM setup for Windows.

`scripts/generate_llms.py` now includes `SUPPORTED_PLATFORMS.md`, and its
summary line names the hosts and the main library areas.

## Verification

- `python3 scripts/check_doc_examples.py` with the released compiler.
- `python3 -m unittest scripts/test_generate_llms.py` and
  `python3 scripts/generate_llms.py --check`.
- The docs site tests and build, and the extension tests.

## Follow-Up

- The compiler's own messages still say "FFI v0" in several diagnostics.
  Changing them means changing fixtures, so it needs its own change.
- Older design checkpoints keep their dated status lines.
- Chapter 17.3 of the book reports measurements made with 0.11.0-dev and
  says so.
- The extension's debugging section covers macOS and Linux. Debugging on
  Windows has not been tried.
