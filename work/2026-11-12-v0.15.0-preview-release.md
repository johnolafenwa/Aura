# Aura 0.15.0 Preview Release

## Goal

Release Aura 0.15.0 as a technical preview. On 2026-11-12 John asked for
it once trait objects, FFI v1, streaming I/O, SIMD, and Array v2 had
landed.

## Cutoff

The candidate holds everything merged since 0.14.0: trait objects steps 2
to 7 (#264), FFI v1 (#262), file reads in pieces with `gzip` and HMAC
(#260), the `regex`, `time`, and `http` modules and the streaming agent
(#265), the fixes from the 2026-11-10 security review (#267), six older
compiler bugs (#268, #270), the two 0.14.0 regressions (#271), inlined
small methods that change their receiver (#272), SIMD (#269), the HTTP
test fix (#275), the `TaskGroup` start delay (#274), and Array v2 items 1
to 4 (#273). Tensor and device interop, the package registry, Linux
arm64, and Windows are not in.

The other threads were asked to hold their merges until the release PR
merged.

## A Slowdown Found And Fixed

The first measurement showed `text_diff` running 17% more instructions
than with 0.14.0, `spreadsheet` 9% more, and `astar_pathfinding` 4% more.
A build of `a41f206` did not show it and a build of `8ae0112` did, so it
came in with #269.

#269 made scalar element reads and writes count as uses of a list's
view, so many more loops read their view once and get a copy that runs
while the view qualifies. When two such loops share blocks, as a loop
and the loop around it do, only the first gets its copy. The second
keeps reading memory. Its selects had already been copied into the first
loop's copy, though, and stayed there as selects, so that copy tested a
flag at every element access: 33 more instructions in each pass of the
`k` loop of `myers` in `text_diff`.

`version_blocks` now remembers the copies it makes of selects that are
not yet settled, and a later call for the same blocks settles those
copies as it settles the originals. `text_diff` runs 1,124M instructions
(1,353M before the fix, 1,160M with 0.14.0), `spreadsheet` 614M (690M,
634M), and `astar_pathfinding` 2,138M (2,189M, 2,103M).

## Measurements

On the shared Linux x86-64 container with 4 vCPUs, at the bench size, the
published 0.14.0 archive (run from a worktree of its tag) and a release
build of the candidate were measured in four passes of five runs each,
alternating, and each time is the median of the twenty. The first two
passes ran before the fix above, so the three programs it changes use
the last two. Each Aura version also ran once under callgrind. The table
for each program is in `benchmarks/cross_language/README.md`.

| Measure | Aura 0.14.0 | Aura 0.15.0 |
| --- | ---: | ---: |
| All 30 programs, wall time | 12.7 s | 12.3 s |
| Median Aura / Rust | 3.1x | 2.9x |
| Median Aura / Python 3.13 | 0.35x | 0.35x |
| Programs faster than Python | 28 | 28 |
| Programs above 8x Rust | 0 | 0 |
| Instructions, all 30 programs | 79,633M | 76,302M |

All 34 programs take 15.6 s, against 56.1 s for Python and 10.8 s for
Rust, and Aura is faster than Python on 32. `file_io` and
`template_render` are still slower than Python.

Things to know:

- The container was busy, and wall times of one compiler moved by 10 to
  30% between passes for `binary_trees`, `interpreter`,
  `markdown_render`, and the threaded programs. The instruction counts
  are the firmer result.
- `http_api` runs 49% more instructions (547M against 368M) and reads 198
  ms against 175. Its source now uses the `http` client. It is still 0.6
  times Rust's time.
- `markdown_render` runs 2.1% more instructions, in
  `run_borrowed_host_builtin`, and `astar_pathfinding` 1.6% more, in the
  runtime's list swap. Neither is traced to a change.
- Linux hello world built by the candidate is 1,117,088 bytes, against
  1,162,576 for the 0.14.0 archive on the same host.
