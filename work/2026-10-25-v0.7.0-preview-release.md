# Aura 0.7.0 Preview Release

## Goal

Release Aura 0.7.0 as a technical preview with phase 2 of Batch 7. LLVM 22
is the only native backend, the runtime fast paths are in, and large
programs build as parallel codegen units. The release is step 12 in the
[Batch 7 design checkpoint](../architecture_docs/22-batch-7-design-checkpoint.md).
It also ships the collection reduction builtins and the editor experience
pass.

## Cutoff

The candidate is cut from `main` at `4b3a6713`, the merge of PR #137.
Hosted CI passed on the PR head `c124ce06` on Linux and macOS, with the
native binaries gates and the documentation examples.

## Work Completed

- Bumped the CLI, compiler, core, runtime, root package, language server,
  and VS Code extension to 0.7.0. The semantic interface stays 20. The
  native cache format is `v10`, up from `v8` in 0.6.0.
- Updated `Cargo.lock` with `cargo update --workspace`, `fuzz/Cargo.lock`
  with `cargo update -p aura-compiler`, and `package-lock.json` with
  `npm install --package-lock-only`. Step 11 left `fuzz/Cargo.lock` stale,
  so cargo also resolved the fuzz lock again. It drops the Cranelift crates
  and adds inkwell, `aura-core`, and `aura-runtime`.
- Pointed the installer, release workflow example, install guides, Manual
  stamp, docs release metadata, CLI README, release process page, and
  tutorial 01 at `v0.7.0-preview`. Regenerated `llms.txt` and
  `llms-full.txt`.
- Moved maintained pages from "Aura 0.6" to "Aura 0.7". The seeded random
  stability promise covers 0.7.x, because the algorithm did not change.
- Corrected pages that phase 2 made false:
  - The CLI README and the CLI page named cache format `v8`. They now name
    `v10`. The release metadata test failed on `main` for this.
  - The performance page gives the `aura` compiler as about 66 MB, since
    it links LLVM statically. Its gaps table carries the 0.7.0 instruction
    ratios. Its Optimization Level and Build Times sections say they
    predate LLVM.
  - The Linux install page lists `libstdc++.so.6`, `libz.so.1`, and
    `libzstd.so.1`, which `aura` loads, and how to install them.
  - Tutorial 01, the examples README, the VS Code extension README and
    INSTALL guide, and the language server README say a source build
    needs LLVM 22 through `scripts/install-llvm.sh`.
- Added a Phase 2 Release Check to the performance page and Step 12
  Results to the checkpoint. Both give the Linux instruction counts against
  Rust and the step 11d build times. Every macOS cell reads
  **TBD (macOS)** until the Mac14,9 run finishes.
- Moved the Unreleased CHANGELOG entries into the 0.7.0 and extension
  0.7.0 sections. The extension section takes the language server and
  VS Code entries. The cache format and the LLVM source build requirement
  join the `sum`, `any`, and `all` names under breaking changes.
