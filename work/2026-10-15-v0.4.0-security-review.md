# 0.4.0 Preview Security Review

## Goal

Review the `v0.4.0-preview` candidate at `53382d17` for security issues, as
John asked alongside the external functional review. Scope: compiler,
runtime, language server, VS Code extension, installer, and the CI and
release workflows. Fix confirmed issues. The functional findings belong to
the release work, not this note.

## Findings Fixed Here

| Severity | Area | Issue | Fix |
| --- | --- | --- | --- |
| High | Language server | Opening an `.au` file ran `target/debug/aura`, `target/release/aura`, or `cargo run` from the opened folder. A cloned repository could ship any program at those paths. | Workspace discovery needs `AURA_LSP_USE_WORKSPACE_COMPILER=1`. The default is `AURA_LSP_AURA_PATH`, then `aura` on `PATH`. The extension also declares that it does not run in untrusted or virtual workspaces. |
| Medium | Release workflow | The extension publish job ran unpinned `npx @vscode/vsce` and `npx ovsx` with `VSCE_PAT` and `OVSX_TOKEN` in the environment of every step. | Exact tool versions, and each token reaches only its own publish step. VSIX packaging uses the same pinned `vsce`. |
| Low | Installer | `curl ... \| sh` ran a partially downloaded script. | The script body is a function called on the last line. |
| Low | CI workflow | `ci.yml` had no `permissions` block, so pushes to `main` got the repository's default token scope. | `contents: read`, the same as the other workflows. |
| Low | HTTP runtime | `Content-Length: +5` and chunk size `+5` were accepted, because Rust integer parsing allows a leading `+`. A proxy that disagrees on framing enables request smuggling. | Lengths must be bare digits. |

## Reported, Not Changed

- Git dependency cache falls back to the shared `$TMPDIR/aura/git` when the
  user cache is not writable. Another local user could pre-seed a checkout
  there.
- Analysis of an opened file resolves its package's git dependencies, so
  opening a project contacts the hosts its `aura.toml` names. Git's default
  protocol policy blocks `ext::`; Aura does not add its own allowlist.
- `SHA256SUMS` ships beside the archives in the same release, so it detects
  corruption but not a compromised release. Build provenance attestations
  would close that gap.
- Manual dispatch with `publish_extension` and a `source_ref` publishes a
  VSIX built from any ref without the tag-match check the GitHub Release
  step has. Only maintainers can dispatch.
- The docs `deploy` job does not wait for the example check. This was also
  in the functional review.

## Checked Without Findings

- Memory safety: 16 adversarial programs for out-of-range list, span,
  string, and Array indexes, overflowing shapes and repetition counts,
  `int64` minimum division, mutation during iteration, and escaping views.
  Each one trapped with a diagnostic on the MIR and direct backends, or the
  checker rejected it.
- Runtime input limits: JSON depth, HTTP header and body sizes, conflicting
  `Content-Length`, chunked plus length, and WebSocket frame and message
  sizes are bounded.
- TLS uses `rustls` with WebPKI roots and no custom verifier.
- Git sources and selectors reject leading `-`, control characters, and
  path-like revisions. Checkouts disable symlinks and reject symlinked trees.
- Native link arguments from `native-link-args.json` are validated. Process
  spawning takes an argument vector, with no shell.
- No credentials are committed. `examples/io/certs/localhost-key.pem` is a
  test key for a loopback TLS example.

## Verification

- Language server: 123 tests pass and coverage stays at 100%. The new
  `untrusted workspace` protocol test fails on `53382d17`, because the planted
  binary runs, and passes with the fix.
- Extension: `check:extension` and 32 tests pass.
- `test:release-packaging` and `test:identity` pass, including new workflow,
  packaging, and truncated-installer tests that fail before the fixes.
- Rust: format, clippy with `-D warnings`, and the `aura-compiler` library
  tests pass.
