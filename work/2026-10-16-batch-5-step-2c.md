# 2026-10-16 Batch 5 Step 2c: Ship libaura_runtime.a

## Goal

Link user executables against the `aura-runtime` static archive instead of
the compiler's, and ship that archive in release packages, per section A of
the [Batch 5 design checkpoint](../architecture_docs/19-batch-5-design-checkpoint.md).

## Work Completed

- `aura build` and direct `aura run` build and link
  `libaura_runtime.a`. A source checkout asks Cargo for the `aura-runtime`
  static archive and its native link arguments. An installed toolchain reads
  `lib/aura/libaura_runtime.a`.
- `aura-compiler` is an rlib only. Nothing links the compiler into a user
  program, so it no longer builds a static archive.
- The native cache format is `aura-native-cache-v7`.
- `scripts/package-cli.sh` packages `libaura_runtime.a` and takes link
  arguments from `aura-runtime`. `install.sh` installs it and removes a
  `libaura_compiler.a` left by an earlier release.
- The CI size job, the binary-size and scalable-runtime benchmarks, and the
  compiler coverage script use the runtime archive.
- The CLI README, install pages, manual cache format and current limits
  pages, and the learn install tree name the new archive.

## Sizes

The release runtime archive is 61,888,200 bytes. The compiler archive it
replaces was 132,235,406 bytes. Executable sizes match step 2a within 4 KiB,
and the contents gate passes on Linux.

## Verification

- `native_cache_format_carries_the_runtime_archive_epoch`, the installed
  layout tests, and the packaged parity test failed until the CLI used the
  new archive and cache format.
- The installer test fails unless `install.sh` removes the stale archive.
- `aura --bin`, `cli`, `backend_parity`, `packages`, `mir_backtraces`, and
  the other `aura` integration targets pass.
- `python3 scripts/check-native-binaries.py` passes against a release build.
- `npm run check:clippy`, `cargo fmt --all --check`,
  `scripts/check-hygiene.sh`, `scripts/generate_llms.py --check`, and the
  release metadata and packaging tests pass.
