# SIMD

Date: 2026-11-11. Asked for by John: "we should implement all the four
core things suggested for the SIMD". The four are wider Array kernels,
more vectorized Array kernels, vectorizable user loops, and explicit
vector types.

## Step 1: wider kernels and new Array kernels

Design records: ADR-0085 and ADR-0086.

What works, on both backends:

- **Kernel dispatch.** On x86-64 every Array kernel is compiled for the
  baseline and for AVX2 (`crates/aura-runtime/src/array_simd.rs`,
  `widest`). The first Array operation of a process picks the copy.
  `AURA_ARRAY_KERNELS=baseline` keeps the baseline copies.
- **`--target-cpu`** on `aura build` and `aura run`, and
  `AURA_TARGET_CPU`: `generic`, `native`, and on x86-64 `x86-64-v2`,
  `x86-64-v3`, `x86-64-v4`. The name is part of the native cache key.
- **`fast_sum()` and `fast_mean()`** add over 32 partial sums in a fixed
  order, the same on every CPU.
- **`dot(other)`** over two Arrays of one shape. The float form adds in
  the reordered order. The integer form is checked.
- **`matmul(other)`** for `[n, k]` with `[k, m]` or `[k]`, and `[k]`
  with `[k, m]`. Each element adds its products in ascending inner
  index, so the result has the bits of the three-loop program.
- **Float `min` and `max`** compare 16 elements at a time and order
  `-0.0` below `0.0`.
- **`sum` and `mean`** no longer scan for a NaN before they add. The
  scan runs only when the result is NaN, to keep the canonical NaN.

Compiler developers: `AURA_DUMP_LLVM_IR=<prefix>` writes each unit's
optimized IR to `<prefix>.<unit>.ll`.

Measured in `benchmarks/simd` on the cloud container, `float64`,
milliseconds:

| Kernel | Aura | Rust | NumPy | Python |
| --- | ---: | ---: | ---: | ---: |
| `sum`, 1,024 elements, 400,000 times | 336 | 305 | 528 | 1,800 |
| `fast_sum`, same | 56 | 55 | | |
| `dot`, same | 120 | 297 | 299 | 19,000 |
| `min` and `max`, same | 196 | 718 | 1,084 | 7,500 |
| `matmul`, 64 by 64, 2,000 times | 108 | 150 | 26 | 42,400 |
| `matmul`, 512 by 512, 4 times | 100 | 232 | 10 | |

`sum` was 662 ms before the NaN scan went. NumPy is ahead on `matmul`
and on a large `dot`: its library fuses multiply and add, uses 512-bit
registers, and runs threads, and its result differs in the last digit.

## Step 2: counted loops over lists

No new language surface. Native code only: `aura run --backend mir` is
unchanged, and both backends give the same output and diagnostics.

- **Range proofs** (`native_codegen_range_loops.rs`). For a loop that
  reads a list's view once, the pass finds `int64` counters compared
  `counter < bound`, follows them through copies and constant offsets,
  and names the accesses that stay in range while two guards hold at the
  loop's entry: the counter starts high enough and the bound ends low
  enough.
- **Versioned copy.** The entry block checks the guards with the view.
  The copy drops the bounds check, the room check of a write, the sink
  test of a `mut` parameter, and the overflow check of the counter's
  advance. `mut` list parameters now get a copy too.
- **`element_address`.** Element addresses are a `getelementptr` from
  one pointer. Before, they were a sum of two words, which hid the stride
  from LLVM's loop vectorizer.
- **Branch weight.** The branch into the copy is weighted 2000 to 1, so the
  register allocator keeps the copy's values in registers.

Tests: eight unit tests of the proof, two backend tests, the
`counted_loops_over_scalar_lists` run fixture, three run-fail fixtures
for an index that leaves the list from inside such a loop, and a CLI test
that reads the optimized IR for a vector load.

Measured in `benchmarks/simd` (`loops.au`, `loops.rs`, `loops.py`),
milliseconds, 1,024 `float64` elements 400,000 times:

| Loop | Aura | Rust | Python |
| --- | ---: | ---: | ---: |
| `scale` | 58 | 62 | 22,800 |
| `saxpy` | 129 | 96 | 20,900 |
| `blur` | 297 | 291 | 45,700 |
| `clamp` | 355 | 349 | 21,100 |
| `dot` | 283 | 284 | 22,900 |

An earlier form of the same program took 2.23 s before this step and
0.7 s after. The rows move by a fifth between runs on the shared host.

Limits, stated in the manual: float reductions and checked integer
arithmetic stay scalar, a loop in a program that starts tasks polls for a
yield on every iteration, and `Array` element loops are not covered.
`range(a, b, step)` with a step runs through a runtime range value and is
slow; a `while` loop with `i += step` qualifies.
