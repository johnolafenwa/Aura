# Phase 5.9: configurable blocking-I/O pool

- Date: 2026-07-27
- Status: complete

## Goal

Implement Provisional ADR-0035 so operators can select the process-wide
blocking-I/O worker count and optionally bound the accepted pending queue,
without blocking Aurora scheduler workers or weakening timeout and
cancellation behavior.

## Documentation completed

- Replaced the stale fixed, nonconfigurable, unbounded-only pool description
  across the architecture guide, Manual, Learn track, tutorials, README, and
  changelog.
- Documented `AURORA_BLOCKING_WORKERS` as an exact positive, unclamped
  override, with the absent default derived from host parallelism, fallback
  `4`, and clamp `2..=8`.
- Documented `AURORA_BLOCKING_QUEUE_CAPACITY` as an optional positive bound on
  accepted pending jobs only. Running jobs and callers awaiting admission do
  not consume the bound; omission preserves the unbounded compatibility mode.
- Documented FIFO scheduler-aware admission, pre-acceptance timeout and
  cancellation, the non-retractable accepted-job boundary, late-result
  disposal, lazy initialization, and fatal pre-user-code `AU4006` validation
  across MIR, direct, and standalone execution.
- Kept the limitation explicit: bounding pending jobs cannot interrupt an
  accepted host call or guarantee unrelated progress while every blocking
  worker remains stuck.
- Added reference-integrity pins and a stale-contract rejection guard.
