# Aura 0.7.0 Security Review And Bug Hunt

## Goal

Review the released 0.7.0 preview (`ab1c970e`) for security issues and
bugs, with most of the time on the LLVM backend and the native fast paths
added since 0.6.0, and fix what turns up.

## Work Completed

- Differential runs: all 667 run-pass fixtures with `main`'s body looped
  three times, and 400 generated programs, matched between MIR and native.
- Valgrind over every run-pass and run-fail fixture, with a debug runtime
  and the box cache capacity set to 0, found no memory errors.
- Native functions now probe frames larger than a page
  (`"probe-stack"="inline-asm"`). Without it, a large frame could step over
  a task stack's single guard page.
- Native `with` bodies that trap on a list index, division, or integer
  overflow leave their exits to the runtime, which records the body's trap
  first. A trapping exit used to replace it.
- Refreshing a native cleanup registration keeps its place, so exits drain
  in reverse registration order after the body changes a resource.
- The language server spawns the absolute compiler path it found and skips
  relative `PATH` entries.
- `aura build` writes its temporary objects and staged runtime archive with
  `create_new` and owner-only permissions.

## Verification

- New run-fail fixtures `manager_exit_trap_keeps_body_*_trap.au` and
  `manager_exit_order_after_mutation.au` fail on 0.7.0 native and pass now.
- An LLVM backend test checks the probe attribute and the page-sized step.
- Runtime, compiler, fixture, backend parity, and language server suites,
  format, and clippy pass. The language server keeps 100% coverage.

## Follow-Up

- Decide which exits still run after an exit traps while the body is
  already failing. The backends differ there, and the manual says each exit
  runs exactly once.
- Native stack headroom check in the frame push, so a task stack overflow
  reports a diagnostic instead of `SIGSEGV`.
- Free the panic payload and task entry boxes on forced task exit (152 bytes
  per failed task).
- Pin the macOS LLVM build.

The full report is in the project files at `release-0.7.0/report.md`.
