# The two regressions the 0.14.0 release measured

Date: 2026-11-11. Asked for by John: close the gaps the 0.14.0 release
left, among them the two regressions against 0.13.0 and two stale manual
pages.

## Goal

1. Fifteen of the 30 cross-language programs execute 2 to 6% more
   instructions on 0.14.0 than on 0.13.0.
2. A hello world executable is about 80 KB larger: 1,080,264 bytes on
   0.13.0 and 1,162,576 on 0.14.0.
3. Two manual pages say associated types and work stealing are
   unavailable.

## How it was measured

- The baselines are the published Linux archives of `v0.13.0-preview`
  and `v0.14.0-preview`, each run with a private `AURA_CACHE_DIR`.
- Each program runs at its bench size under callgrind. The fifteen
  regressions reproduce: `regex_match` +6.2%, `lzw_compress` +5.8%,
  `sql_engine` +5.4%, `task_pool` +4.2%, `interpreter` +3.8%, down to
  `template_render` +1.3%. The 30 programs total 79,994M instructions on
  0.13.0 and 79,828M on 0.14.0.
- A runtime change is measured by building `libaura_runtime.a` from a
  worktree of the 0.14.0 tag with the change applied, and putting it in a
  copy of the 0.14.0 archive beside the published compiler. Nothing but
  the runtime differs from the release.
- Symbols come from a build with a `strip` on `PATH` that does nothing.
  Hello world's growth is the difference in `nm --size-sort` between the
  two releases, and the reason code is kept is the call graph read from
  `objdump`, with calls through the global offset table resolved from
  the relocations.

## Causes and fixes

### Hello world size

- `print` renders a value through `Value::render_inner`. For a
  `json.Value` that lies in a parsed document's tape it asked for the
  payload as a value, and for an array or an object that builds a list
  or a dict. That one call kept the typed list forms, the dict index, its
  hashing, and value equality in every executable that prints: 60,651
  bytes of the 82,312 added.
- `render_inner` now reads a tape value's payload in pieces from the tape
  (`JsonNode::payload_parts`) and reads every other variant's payloads
  through `VariantPayloads::stored`, which has no tape arm. The text is
  the same.
- Hello world is 1,089,808 bytes with the 0.14.0 compiler and the fixed
  runtime. The 9.5 KB that remain are spread over code 0.14.0 added to
  paths every program has.

### Instruction counts: the runtime

1. **A new list looked its element type up by name.**
   `aura_direct_vec_empty_tagged` cloned the element type out of the
   list's type tag and passed it to `SharedType::from`, which compares
   the name against five common names before it allocates. That is about
   76 instructions for every new list, and 474M over the fifteen
   programs. The type tag now holds the element type shared once
   (`RuntimeTypeTag::list_element`), and a new list takes a reference.
   Places that built `Type::named("str")` only to share it call
   `SharedType::named`.
2. **Every dict read tested its storage twice.** The dict storage became
   `Eager(Small | Large) | Lazy` when a parsed JSON object learned to
   stay in its tape. A read first asked whether the entries were lazy and
   then which eager form they had, with a call between the two tests that
   LLVM could not see through. `Storage` is now `Small | Large | Lazy`,
   and the lazy arm is a cold function.
3. **Freeing a value called two functions.** The value header's `Drop`
   and the ledger's unlink stopped being inlined into the code that frees
   a box. Both are inlined again, the unlink moves the last linked value
   into the freed slot without a bounds test, and the lock of a value
   shared between threads is freed in a cold function.

What stays: the smaller value header of 0.14.0 keeps the task's ledger in
a vector, which costs about 5 instructions more per new box than the
linked list did, a dict read tests once for a tape object, and a new box
tests once for a variant that keeps its block inline. Those bought the
memory and JSON gains of 0.14.0.

### Instruction counts: the compiler

- A loop that reads a list view once has two copies
  (`FunctionBackend::version_blocks`). A function the loop calls then has
  two calls. LLVM inlines a local function with one call whatever its
  size, and weighs two calls against the function's size, so `compare` in
  `sql_engine`, `heap_pop` in `graph_paths`, and `escape` in
  `template_render` stopped being inlined.
- The LLVM backend now records the callee of each direct call a loop
  copy doubles. Before it writes the object it marks a local function
  `alwaysinline` when its calls are one call and that call's copies, no
  function or data object takes its address, it does not call itself,
  and it has at most 1,024 recorded instructions. Calls in functions the
  program cannot reach, such as unused thunks, do not count. A debug
  build is left alone.

### Manual pages

The 0.14.0 release PR corrected the manual: `generics-and-traits.md`
documents associated types, and `current-limits.md`, `concurrency.md`,
`status-and-compatibility.md`, and `conformance.md` describe work
stealing of children that have not started. A search of `docs/` for both
terms finds no page that says either is unavailable. Two architecture
pages still described spawn-time pinning with no stealing,
`07-mir-runtime.md` and `05-semantic-analysis.md`, and now describe
placement as ADR-0072 records it.

- The table lists the fifteen programs 0.14.0 regressed. Of the other
  fifteen, none is more than 0.3% above 0.13.0.
- `task_pool` runs tasks on four workers, and its count moves by about 4%
  between runs.
- `compare`, `heap_pop`, and `escape` are inlined again. The call-frame
  instructions of `sql_engine`, `graph_paths`, and `template_render`
  match 0.13.0.
- Hello world: 1,162,576 bytes on 0.14.0 and 1,089,808 with the fixed
  runtime. On `main`, 1,167,304 before and 1,098,640 after.
- `scripts/bench-cross-language.py --check` and
  `scripts/bench-operation-probes.py --check` pass with the release
  build: 31 programs and 27 probes print the expected lines.
- `cargo test -p aura-runtime --lib` passes, 1,051 tests. `cargo test -p
  aura-compiler --lib` passes but for
  `package_io_helpers_cover_local_error_paths`, which fails only when the
  tests run as root. `cargo clippy` with `-D warnings` is clean for both
  crates.
- New tests: `a_tape_value_renders_from_the_tape_as_its_values_render`
  and `a_tape_values_parts_count_what_is_left` in the runtime, and three
  LLVM backend tests for the inlining rule.

## Remaining work

None for the two regressions. `bank_ledger`, `interpreter`,
`binary_trees`, and `markdown_render` stay 1 to 2% above 0.13.0 for the
reasons under "What stays".
