# Aura 0.17.0 Preview Release

## Goal

Release Aura 0.17.0 as a technical preview. On 2026-11-23 John chose to
have the work that Codex left finished, landed on `main`, and prepared
as the 0.17.0 preview.

## Cutoff

The candidate holds everything merged since 0.16.0, up to `07337c84`:
the documentation and book work (#294, #295, #296), three compiler fixes
(#297), and the features that were built on the `codex/aura-integration`
and `codex/aura-combined-candidate` branches and landed together in #310:
first-class closures and local functions, set algebra, byte strings and
text encodings, the `numbers`, `collections`, `sync` and `image`
modules, recovery from a trapped call (`control.recover`), the second
step of the C interface, and the raylib package. No other pull request is open.

The combined candidate branch held failure recovery and the fixes and
tests that came from running the features together, and none of that had
reached the integration branch. #310 merged the two, and every feature
branch tip equals a head that was merged into one of them.

## Measurements

On the shared Linux x86-64 container with 4 vCPUs, at the bench size, the
published 0.16.0 archive (run from a worktree of its tag) and a release
build of the candidate were measured in four passes of five runs each,
alternating, and each time is the median of the twenty. Each Aura version
also ran once under callgrind. The benchmark sources are the same in both
tags. The table for each program is in
`benchmarks/cross_language/README.md`.

| Measure | Aura 0.16.0 | Aura 0.17.0 |
| --- | ---: | ---: |
| All 34 programs, wall time | 14.6 s | 13.5 s |
| Median Aura / Rust | 2.9x | 2.6x |
| Median Aura / Python 3.13 | 0.35x | 0.34x |
| Programs faster than Python | 31 | 32 |
| Programs above 8x Rust | 0 | 0 |
| Instructions, all 34 programs | 104,718M | 103,433M |

Python takes 51.8 s and Rust 10.0 s in the same passes. The container
was busier than on 14 November, when the same 0.16.0 programs took
12.1 s.

Things to know:

- `astar_pathfinding` runs 901.7M instructions against 2,138.0M and
  takes 137 ms against 288. A profile of the 0.16.0 build spends 35% of
  its instructions in `aura_direct_vec_swap_in_place` and another 26% in
  what it calls. The 0.17.0 build makes no such call: the swap of two
  elements of one list is compiled into the function.
- `lzw_compress` (-3.2%), `stream_io` (-2.8%) and `sort_records` (-2.7%)
  also run fewer instructions.
- `interpreter` runs 2.1% more instructions, `raytracer` 1.5% more and
  `order_book` 1.2% more. In `interpreter`, `IndexedEntries::position`
  runs 7% more instructions than in 0.16.0 and accounts for about half of
  the growth. Dictionary storage has a fourth form, the union of two
  ordered sets held as a view, and every lookup tests for it. The causes
  in `raytracer` and `order_book` were not looked for.
- Every other program is within 0.6% of its 0.16.0 instructions.
- The wall time differences other than `astar_pathfinding` are the
  container's. `file_io` reads 1,101 ms against 1,786 on the same
  instructions, and its 0.16.0 medians ran from 992 to 2,093 ms between
  passes. `csv_aggregate` reads 430 ms against 458 with Python at 442,
  which is why 0.16.0 counts 31 programs faster than Python here.
- `file_io` and `template_render` are still slower than Python.
- Linux hello world built by the candidate is 1,171,576 bytes, against
  1,135,440 for the 0.16.0 archive on the same host. The 36 KB is spread
  over many functions. The largest are the cleanup stack that recovery
  from a trapped call unwinds (`drain_direct_cleanup_stack`, the task
  runtime state), the code that drops, copies and prints the new kinds
  of value, and `cbrt` and `fma` from the math library.

## Work Completed

- Bumped the CLI, compiler, core, runtime, `aura-mem`, root package,
  language server, and VS Code extension to 0.17.0. The semantic
  interface stays 20, and the native cache format stays `v10`.
- Updated `Cargo.lock`, `fuzz/Cargo.lock` and `package-lock.json`. The
  fuzz lock file gained the packages that the new modules depend on.
- Pointed the installers, package scripts, release workflow example,
  install guides, Manual stamp, docs release metadata, CLI README,
  release process page, and book at `v0.17.0-preview`, and reframed the
  maintained pages as Aura 0.17. The seeded randomness promise now covers
  the 0.17.x series. Regenerated `llms.txt` and `llms-full.txt`.
- The failure recovery page says the feature is available since 0.17.0.
  It pointed at the Unreleased section of the changelog.
- Recorded the results in the cross-language README and the performance
  page.
- Moved the Unreleased entries into the 0.17.0 and extension 0.17.0
  sections.
- `python3 -m unittest scripts/test_release_metadata.py` passes.
