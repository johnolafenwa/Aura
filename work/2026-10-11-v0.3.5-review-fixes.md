# 0.3.5 Review Fixes

## Goal

Verify and fix the defects reported by an external review of
`v0.3.5-preview` at `420ddbef`. Every finding reproduced on `main` at
`fd188d9`.

## Work Completed

| Finding | Cause | Fix |
| - | - | - |
| P1 returned view through a field between selections fails on direct | `returned_element_alternative` kept the trailing `.` of each field group, so the runtime path read `[i].values..[i]` | Trim both ends of each field group in `native_codegen.rs` |
| P2 keyword `list.set` beside a live view | `lower_vec_set_beside_loans` refused any named argument, so the ordinary receiver call hit the live loan | Bind arguments through the `VecSet` contract and keep source evaluation order |
| P2 grouped or field receiver for a disjoint `set` | The checker treated only a bare local name as a collection operation | `is_collection_mutation_receiver` accepts a local, a group, or a field path of a local, and falls back to the ordinary read when a part is moved |
| P2 float entry views | The MIR lowering kept a float literal as an operand the loan validator refuses, the MIR runtime could not encode a float key, and the direct handoff applied `uextend` to an `f64` | Copy non-literal selectors to a temporary, encode float keys by their bits, and bitcast float selectors across the direct handoff |
| P2 wide integer entry views on MIR | The MIR runtime parsed every integer key as `i64` | Encode and parse the full integer value |

Two related defects were fixed in the same pass:

- Entry views with enum keys failed on MIR. Keys without a scalar form now
  use a canonical, length-prefixed encoding `[k:v:<hex>]`, matched against
  each stored key's own encoding.
- `view x = f(table, 18446744073709551617)` with an `int128` parameter
  failed in the checker. Returned-view type inference now types each
  argument with its parameter type as the hint.

The MIR runtime names a loaned entry by the stored key rather than the
selector, so a later access finds exactly that entry.

## Verification

- Six new run-pass fixtures fail on `main` and pass on both backends:
  `returned_view_field_between_selections`, `element_set_keyword_arguments`,
  `element_set_projected_receivers`, `entry_view_float_keys`,
  `entry_view_wide_integer_keys`, and `entry_view_enum_keys`. The forced
  backend parity matrix runs every run-pass fixture.
- Negative controls still reject: an overlapping `set` or a structural call
  on a field receiver under a live element view reports `AU3011`, a moved
  field receiver reports `AU3001`, and an immutable field receiver reports
  `AU3003`.
- `cargo test --workspace` and `cargo fmt --all --check`.

The native cache key covers the MIR, the runtime archive, and the package
version, not the compiler build. A source checkout that changes codegen
without a version bump can reuse a stale cached binary, so set
`AURA_CACHE_DIR` to a fresh directory when checking a codegen fix locally.
