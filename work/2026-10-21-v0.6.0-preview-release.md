# Aura 0.6.0 Preview Release

## Goal

Release Aura 0.6.0 as a technical preview with Batch 6 and phase 1 of
Batch 7. Batch 6 adds typed JSON codecs, derived schemas, and decorators.
Batch 7 phase 1 makes native code faster on Cranelift. The release is the
second half of step 7 in the
[Batch 7 design checkpoint](../architecture_docs/22-batch-7-design-checkpoint.md).

## Cutoff

The candidate is cut from `main` at `d78c0714`, the merge of PR #98. Hosted
CI passed on the PR head `445163e7` on Linux and macOS, with the native
binary gates and the documentation examples.

## Work Completed

- Bumped the CLI, compiler, core, runtime, root package, language server,
  and VS Code extension to 0.6.0. The semantic interface is 20, up from 19
  in 0.5.0, and the native cache format is `v8`.
- Updated `Cargo.lock`, the `aura-compiler` entry in `fuzz/Cargo.lock`, and
  `package-lock.json`.
- Pointed the installer, release workflow example, install guides, Manual
  stamp, docs release metadata, CLI README, release process page, and
  tutorial 01 at `v0.6.0-preview`. Regenerated `llms.txt` and
  `llms-full.txt`.
- Moved maintained pages from "Aura 0.5" to "Aura 0.6". The seeded random
  stability promise covers 0.6.x, because the algorithm did not change.
- Corrected pages that 0.6 made false. The control-plane, bytes, and
  current-limits pages and tutorial 21 no longer say Aura lacks derived
  codecs or schemas, and they link to the JSON page's typed codecs. Tutorial
  14 lists the typed codec functions and decorators. The CLI README, the
  compiler README, and the CLI, diagnostics, and status pages name semantic
  interface 20 and cache format `v8`.
- The stale-minor release metadata test skips code, so a numeric literal
  such as `0.5` no longer reads as an old release.
- Moved the Unreleased CHANGELOG entries into the 0.6.0 and extension 0.6.0
  sections, with added, changed, performance, and fixed entries. No entry
  breaks source written for 0.5.0.

## Measurements

The release candidate ran against the Rust references on the Linux
container and the macOS arm64 baseline host. The table is in the
performance manual's Phase 1 Release Check. Four of six programs meet their
phase 1 targets on both hosts.
